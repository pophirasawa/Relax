# 02 Checkpoint 断点续训验证报告

逐项数据：`results/resume-verify.json`。

## 1. 验证目标

该实验验证 Mixture-of-LoRA 在真实 Qwen3-4B GRPO 训练中保存的 distributed
checkpoint 能否恢复以下状态：

- expert A/B 与 router 参数。
- Adam optimizer state 和参数分片 metadata。
- optimizer scheduler 与当前 iteration。
- RNG 状态。
- rollout 数据进度。
- 恢复后的训练指标和 expert 路由行为。

主实验在 iteration 49 保存 checkpoint。恢复任务从该快照启动，继续完成 step
50、51、52。

## 2. 恢复方法

1. 复制 `iter_0000049`、checkpoint tracker 和 dataset state，保持原始快照只读。
2. 使用与主实验相同的模型、数据、并行方式、optimizer、scheduler 和 Mixture 配置。
3. 保持 `num_rollout=200`，确保 scheduler 总步数与 checkpoint metadata 一致。
4. 加载完整 distributed checkpoint，不启用 optimizer/RNG 跳过或状态重置选项。
5. 对比主任务和恢复任务在 step 50–52 的数据位置、学习率、训练指标和路由分布。

真实续训用于验证系统恢复流程。固定 batch 下的逐值一致性由自动化 checkpoint 测试
覆盖，因为带温度采样的 RL rollout 无法要求两次生成逐 token 相同。

## 3. 验收结果

| 验收点 | 判定 | 证据 |
|---|---|---|
| 从正确 iteration 继续 | 通过 | 加载 iteration 49，恢复任务新增 step 50、51、52 |
| 数据进度恢复 | 通过 | dataset state 的 offset 与 rollout batch、采样数一致 |
| optimizer/scheduler 恢复 | 通过 | fully reshardable optimizer shard 和 scheduler metadata 加载成功 |
| RNG 与训练状态可继续 | 通过 | 未启用 RNG reset，连续完成三个有效 optimizer step |
| expert/router 状态恢复 | 通过 | 固定 batch 测试一致，真实续训路由分布与主任务连续 |
| loss/reward/grad norm 稳定 | 通过 | 三步指标均为有限值，无异常跳变 |

## 4. Iteration 与数据进度

恢复日志确认 checkpoint iteration 为 49。TensorBoard 没有重新写入 step 0 或重复
step 49，只新增 step 50–52。

Dataset state：

| 字段 | 值 | 解释 |
|---|---:|---|
| `sample_offset` | 816 | 51×rollout batch 16 |
| `epoch_id` | 0 | 仍位于首个 epoch |
| `sample_group_index` | 816 | 与 sample offset 一致 |
| `sample_index` | 6528 | 816×8 samples/prompt |

这些值表明恢复任务从主任务保存位置继续读取数据，没有从数据集开头重新采样。

## 5. Optimizer 与 scheduler

恢复过程读取 fully reshardable optimizer metadata，并完成 iteration 49 checkpoint
加载。启动配置中：

- `no_load_optim` 未启用。
- `no_load_rng` 未启用。
- `reset_optimizer_states=False`。
- scheduler 总步数与 checkpoint 保持一致。

三个 step 的学习率逐值一致：

| step | 主任务 | 恢复任务 |
|---|---:|---:|
| 50 | 9.999999747378752e-06 | 9.999999747378752e-06 |
| 51 | 9.999999747378752e-06 | 9.999999747378752e-06 |
| 52 | 9.999999747378752e-06 | 9.999999747378752e-06 |

本实验使用 constant learning rate，学习率相同本身不足以证明 optimizer state 完整。
完整证据来自 optimizer shard 加载、未启用 reset/skip 选项、scheduler metadata 校验，
以及自动化测试中的恢复后下一步参数一致性。

## 6. 训练指标

下表给出恢复任务相对主任务同 step 的变化。Grad norm 列同时保留两组绝对值：

| step | router aux loss | entropy loss | grad norm（主任务 → 恢复） |
|---|---:|---:|---:|
| 50 | -0.10% | -0.23% | 0.00718 → 0.00897 |
| 51 | -0.23% | -1.56% | 0.00867 → 0.01023 |
| 52 | -0.04% | +2.81% | 0.01088 → 0.01080 |

Router aux loss 三步偏差均小于 0.25%。Grad norm 保持在 `7e-3` 到 `1.1e-2`
范围，第三步与主任务差异收敛到约 0.7%。所有 loss、reward、KL、entropy 和 grad norm
均为有限值。

GRPO 的组内归一化 reward 均值接近 0，对接近 0 的数计算相对百分比会产生失真的大
比例。稳定性判断使用有量纲的 raw reward、loss 量级和 grad norm，不使用接近 0 的
归一化 reward 比值。

## 7. Expert 路由分布

四个 expert 的 post-Top-K 平均激活权重如下：

| step | 来源 | expert 0 | expert 1 | expert 2 | expert 3 |
|---|---|---:|---:|---:|---:|
| 50 | 主任务 | 0.257256 | 0.243007 | 0.250064 | 0.249673 |
| 50 | 恢复任务 | 0.260153 | 0.240411 | 0.248121 | 0.251316 |
| 51 | 主任务 | 0.259799 | 0.240069 | 0.248613 | 0.251518 |
| 51 | 恢复任务 | 0.256848 | 0.240840 | 0.249557 | 0.252754 |
| 52 | 主任务 | 0.256308 | 0.240994 | 0.249453 | 0.253245 |
| 52 | 恢复任务 | 0.259035 | 0.241641 | 0.248854 | 0.250470 |

最大绝对偏差约为 0.003。Expert 0 保持较高激活，expert 1 保持较低激活，四个 expert
仍接近均衡，未出现恢复后路由突变或单 expert 塌缩。

真实续训中的路由分布属于行为一致性证据。参数逐值恢复由 distributed checkpoint
加载、固定 batch 输出/路由对比和恢复后下一步参数测试共同证明。

## 8. 恢复耗时与显存

| step | 主任务 step time | 恢复任务 step time |
|---|---:|---:|
| 50 | 300.20s | 535.05s |
| 51 | 291.73s | 273.15s |
| 52 | 267.30s | 302.83s |

恢复后的第一个 step 包含 checkpoint 加载后的首次权重同步、SGLang 初始化和 CUDA
cache 建立，因此耗时明显增加。后续 step 回到正常区间。该冷启动 step 不进入三组
稳态性能比较。

恢复任务采样到的单卡系统峰值显存为 63,496 MiB，与 Mixture 主实验的峰值范围一致。

## 9. 复核方法

```bash
python scripts/analyze-resume.py \
  <mixture-main-tensorboard> \
  <mixture-resume-tensorboard> \
  results/resume-verify.json
```

## 10. 结论

Checkpoint 恢复覆盖模型、expert、router、optimizer、scheduler、RNG、iteration 和
数据进度。恢复任务连续完成三个训练 step，训练与路由指标保持正常，满足 Task 25
对 checkpoint 保存和恢复一致性的验收要求。
