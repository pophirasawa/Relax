# 00 实验环境与设计

## 1. 实验目标

补充实验回答三个问题：

1. Task 25 新增的 CUDA、分布式 checkpoint 和真实 PEFT 包装测试能否在完整后端环境通过。
2. Mixture checkpoint 能否恢复模型、optimizer、scheduler、RNG 和数据进度并继续训练。
3. 当前 Mixture 实现相对全参和单 LoRA 的系统吞吐与显存开销是多少。

## 3. 最终 workload

| 配置 | 值 |
|---|---:|
| rollout batch size | 16 |
| samples per prompt | 8 |
| global batch size | 128 |
| 最大 response 长度 | 8192 |
| 最大训练 tokens/GPU | 9216 |
| rollout log-prob tokens/GPU | 30720 |
| Tensor Parallel | 2 |
| Sequence Parallel | 开启 |
| Pipeline Parallel | 1 |
| Context Parallel | 1 |
| SGLang engine 数 | 8 |
| 每个 SGLang engine GPU 数 | 1 |
| SGLang 静态显存比例 | 0.7 |
| Actor recompute | full / uniform / 1 layer |
| 优化器 | Adam，beta=(0.9, 0.98)，weight decay=0.1 |
| LR schedule | constant |

三个性能组仅改变训练参数范围和 LoRA 配置：

| 组 | 可训练范围 | 学习率 | LoRA/router |
|---|---|---:|---|
| 全参 | 全部 actor 参数 | 1e-6 | 无 |
| 单 LoRA | 单个 adapter | 1e-5 | rank 16、alpha 32 |
| Mixture-LoRA | 4 个 expert 与 router | 1e-5 | rank 16、alpha 32、Top-K 2、temperature 1.0、aux coefficient 0.01 |

LoRA 两组都作用于 `linear_qkv` 和 `linear_proj`，dropout 为 0。学习率差异符合两种
训练方式的正常设置；constant schedule 下，它不会改变每个 step 的算子数量。

## 4. 对照设计

为保证结果可比，三组保持以下条件一致：

- 模型 checkpoint 和 tokenizer。
- DAPO math 数据及字段配置。
- rollout batch、采样数、temperature 和最大 response 长度。
- global batch、动态 batch 和每卡 token 上限。
- TP/SP/PP/CP 并行配置。
- colocate 资源分配和 SGLang 静态显存比例。
- BF16、FP32 梯度归约和 attention softmax 精度。

全参和单 LoRA 各运行 12 step。Mixture 使用 200-step 主实验中相同的 step 下标，
统一比较 step 2–11。

## 5. 指标定义

| 指标 | 定义 |
|---|---|
| step time | 一个完整 GRPO step 的 wall time |
| rollout time | 生成与 rollout 处理阶段耗时 |
| actor train time | actor forward、backward 和 optimizer 阶段耗时 |
| response 吞吐 | 生成的 response token 数除以 rollout time |
| actor train 吞吐 | actor 处理的训练 token 数除以 actor train time |
| 系统峰值显存 | 统计窗口内所有 GPU 的单卡最大 `memory.used` |
| 平均 response 长度 | 统计窗口内生成 response 的平均 token 数 |

显存通过 5 秒间隔的 NVML 采样获得。统计脚本使用 TensorBoard event 的 wall time
确定 step 2–11 对应时间范围，再过滤同一窗口内的 GPU 样本。

## 6. 统计限制

- 十步窗口适合验收和初步性能判断，无法替代多次重复运行。
- RL rollout 带随机采样，同一配置各 step 的 response 长度和耗时仍会波动。
- Mixture 与对照来自不同实验批次，环境规格一致，但无法消除批次间系统噪声。
- Colocate 峰值显存主要由 rollout 的 KV cache 和生成 batch 决定，不能直接衡量
  actor optimizer state 的节省。
- 本轮比较系统效率，没有比较三种方法在相同 wall-clock 或 token budget 下的最终 reward。
