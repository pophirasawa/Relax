# 03 全参、单 LoRA 与 Mixture-LoRA 性能实验

逐项数据：

- `results/three-way-window-2-11.json`：耗时、吞吐、响应长度和端到端峰值。
- `results/actor-memory-window-2-11.json`：actor 阶段显存区间与汇总值。

图片：

- `results/figures/perf-curves.png`：step 2–11 逐步耗时和吞吐。
- `results/figures/perf-window-means.png`：统一窗口的耗时、吞吐和响应长度均值。
- `results/figures/perf-overhead-breakdown.png`：Mixture 相对单 LoRA 的变化和耗时分解。
- `results/figures/perf-memory-phases.png`：actor 阶段显存及其与端到端峰值的对照。

## 1. 实验目标

在相同 Qwen3-4B DAPO GRPO workload 下比较：

1. 全参数训练的系统吞吐和容量需求。
2. 原有单 LoRA 路径是否受 Task 25 修改影响。
3. 当前 dense Mixture 路径相对单 LoRA 增加的训练与 rollout 成本。

## 2. 三组配置

| 组 | 每个 TP rank 的可训练参数 | 学习率 | LoRA 配置 | Rollout 执行 |
|---|---:|---:|---|---|
| 全参 BF16 | 2,015,755,776 | 1e-6 | 无 | 标准 Qwen3 模型 |
| 单 LoRA | 4,423,680（0.22%） | 1e-5 | rank 16、alpha 32 | 固定 adapter 合并进 base |
| Mixture-LoRA | expert 17,694,720 + router 663,552（0.90%） | 1e-5 | 4 experts、rank 16、Top-K 2 | token 路由 external model |

参数数量来自 TP=2 下单个模型 rank 的启动统计，用于比较同一并行配置中的可训练比例，
不代表 Qwen3-4B 的全局参数总量。

LoRA 两组均使用：

- `lora_rank=16`。
- `lora_alpha=32`。
- target modules 为 `linear_qkv` 和 `linear_proj`。
- dropout 为 0。

Mixture 额外使用 4 个 expert、Top-K 2、router temperature 1.0 和 aux loss coefficient
0.01。完整 workload 见 `00_环境与前提.md`。

## 3. 统计窗口

三组统一统计 step 2–11，共 10 个 step。选择依据如下：

- Step 0 的耗时为 509.6 秒，包含明显初始化开销。
- Step 1 起进入 259–308 秒的正常区间。
- 全参和单 LoRA 各运行 12 step，能够提供相同下标的比较窗口。
- Mixture 虽运行 200 step，统计与绘图仍只读取 step 2–11。
- 窗口内没有 checkpoint 保存。

Mixture 不同窗口的 step time：

| 窗口 | step 数 | 平均 step time | 相对 step 10–59 |
|---|---:|---:|---:|
| 10–59 | 49 | 271.56s | 基准 |
| 10–29 | 20 | 273.02s | +0.5% |
| 10–20 | 11 | 272.54s | +0.4% |
| 2–11 | 10 | 281.68s | +3.7% |

Step 2–11 中恰好包含两个较慢 step，因此绝对均值比长窗口高 3.7%。三组使用相同
下标保证比较口径一致，但不能消除 RL 生成和系统调度波动。

## 4. 原始结果

| 指标 | 全参 | 单 LoRA | Mixture-LoRA |
|---|---:|---:|---:|
| step time (s) | 218.98 | 219.11 | 281.68 |
| rollout time (s) | 111.72 | 113.79 | 155.61 |
| actor train time (s) | 78.61 | 76.92 | 89.91 |
| response 吞吐 (tok/s) | 3964.85 | 3952.03 | 3075.76 |
| actor train 吞吐 (tok/s) | 11293.67 | 11511.07 | 9851.78 |
| actor 阶段系统显存均值 (MiB/GPU) | 38,259 | 26,669 | 29,158 |
| actor 阶段系统显存 P95 (MiB/GPU) | 46,391 | 30,100 | 32,190 |
| actor 阶段系统显存峰值 (MiB/GPU) | 47,550 | 31,258 | 33,678 |
| 窗口内系统峰值显存 (MiB) | 61,632 | 61,656 | 63,494 |
| 整个作业系统峰值显存 (MiB) | 62,268 | 61,656 | 64,084 |
| 平均 response 长度 (token) | 6787.07 | 6767.17 | 6773.76 |

三组平均 response 长度相差不到 0.3%。Step time 和吞吐差异没有被明显不同的生成
长度混淆。

## 5. 显存统计

端到端统计读取 TensorBoard event 的 wall time，确定 step 2–11 从 step 1 完成到
step 11 完成的时间范围，再过滤同期 5 秒间隔 NVML 采样。窗口峰值为过滤后所有 GPU
的最大 `memory.used`。

该值表示 colocate 系统的单卡容量需求，包含：

- Megatron actor 参数、激活、梯度和 optimizer state。
- SGLang 静态显存池。
- KV cache 和生成 batch。
- Colocate 阶段切换时仍驻留的缓存。

三组统一设置 `sglang-mem-fraction-static=0.7`，SGLang rollout 会预留相近大小的静态
显存池，生成阶段的 KV cache 和 batch 又会把显存推到该容量附近。端到端峰值因此都
接近 60–62 GiB，主要反映 rollout 显存配额，而非 actor 训练方式的显存差异。

Actor 阶段使用每个 step 的 `actor_train_time`、`update_weights_time` 和指标写入时间
重建训练区间，并汇总区间内全部 GPU 的 NVML 样本。统计结果为：

| 组 | 均值 | P95 | 峰值 | 单卡均值范围 |
|---|---:|---:|---:|---:|
| 全参 | 38,259 MiB | 46,391 MiB | 47,550 MiB | 37,485–38,777 MiB |
| 单 LoRA | 26,669 MiB | 30,100 MiB | 31,258 MiB | 25,341–27,433 MiB |
| Mixture-LoRA | 29,158 MiB | 32,190 MiB | 33,678 MiB | 27,526–30,564 MiB |

按均值比较，单 LoRA 比全参减少 11,590 MiB（30.3%），Mixture-LoRA 比全参减少
9,101 MiB（23.8%）。Mixture-LoRA 比单 LoRA 增加 2,490 MiB（9.3%），对应额外三组
expert 和 router 的参数、梯度、optimizer state 以及 dense expert 中间结果。

这仍是 colocate 系统显存，包含 actor 阶段驻留的 SGLang 进程。它能比较相同部署方式下
训练阶段的容量差异，但不能拆成纯 actor 参数、激活和 allocator cache。

## 6. 复核命令

统计脚本不依赖固定机器路径：

```bash
python scripts/summarize-perf-window.py \
  <full-param-run> <single-lora-run> <mixture-run> \
  --start 2 --end 11 \
  --json results/three-way-window-2-11.json
```

重新生成三张性能图：

```bash
python scripts/plot-perf-comparison.py \
  --out-dir results/figures \
  --run "Full-param:<full-param-run>" \
  --run "Single-LoRA:<single-lora-run>" \
  --run "Mixture-LoRA:<mixture-run>" \
  --start 2 --end 11
```

重算并绘制 actor 阶段显存：

```bash
python scripts/summarize-actor-memory.py \
  --run "Full-param:<full-param-run>" \
  --run "Single-LoRA:<single-lora-run>" \
  --run "Mixture-LoRA:<mixture-run>" \
  --start 2 --end 11 \
  --json results/actor-memory-window-2-11.json

python scripts/plot-memory-comparison.py \
  --actor-json results/actor-memory-window-2-11.json \
  --perf-json results/three-way-window-2-11.json \
  --output results/figures/perf-memory-phases.png
```

## 7. 结论

单 LoRA 与全参在该窗口中的 step time 相差 0.06%，原有单 LoRA 路径没有出现明显
系统吞吐回归。当前 dense Mixture 的 step time 比单 LoRA 增加 28.56%，rollout
阶段是主要增量来源。详细分解见 `04_三组对比结论.md`。
